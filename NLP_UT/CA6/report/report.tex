\begin{abstract}
This paper presents the design and implementation of a coding agent capable of autonomous software debugging and enhancement. The agent utilizes Large Language Models (LLMs) with tool integration to interact with codebases, execute commands, and apply fixes. We evaluate the agent's performance on three NLP-related projects: a legacy CSV processor, a vector-based retrieval system (TinyRAG), and a bigram language model. Results demonstrate the agent's effectiveness in identifying and resolving complex issues, achieving 100\% test pass rates across all projects while implementing mathematically rigorous solutions. The agent successfully applied techniques including Laplace smoothing, TF-IDF weighting, and robust error handling, showcasing advanced problem-solving capabilities beyond simple code generation.
\end{abstract}

\section{Introduction}

The emergence of Large Language Models (LLMs) has revolutionized software development by enabling AI-assisted coding. However, most LLM applications remain limited to code generation and explanation. This work explores the next frontier: autonomous agents capable of interacting with existing codebases, debugging errors, and implementing enhancements.

We present a coding agent that combines LLM reasoning with practical tool integration, enabling it to read files, execute commands, and modify codebases autonomously. The agent is evaluated on three diverse NLP projects, demonstrating its ability to handle complex debugging tasks across different domains.

def read_file(file_path: str) -> str:
    """Read the content of a file."""
    try:
        target = _get_safe_path(file_path)
        if not target.exists():
            return f"Error: File {file_path} does not exist."
        if not target.is_file():
            return f"Error: {file_path} is not a file."

    except Exception as e:

@tool
def list_files(directory: str = ".") -> str:
    """List files and directories in the specified path."""
    try:
        target_dir = _get_safe_path(directory)
        if not target_dir.exists():
            return f"Error: Directory {directory} does not exist."
        
        items = []
        for item in target_dir.iterdir():
            if item.name.startswith("."):  # Skip hidden files
                continue
            kind = "DIR" if item.is_dir() else "FILE"
            items.append(f"[{kind}] {item.name}")
        return "\n".join(sorted(items))
    except Exception as e:
        return f"Error listing files: {str(e)}"

Advanced context pruning prevents token limit issues while preserving critical information:

\begin{lstlisting}[language=Python, caption=Intelligent Context Pruning]
def _prune_context(self):
    """Advanced context management with content-aware pruning."""
    try:
        state = self.graph.get_state(self.config)
        messages = state.values.get("messages", [])
    except Exception:
        return

    pruned_messages = []
    total_content_length = 0
    max_context_length = 100000  # Approximate token limit buffer
    
    for msg in messages:
        content = getattr(msg, "content", "")
        content_length = len(content)
        
        # Prune long tool outputs
        if (isinstance(msg, ToolMessage) and content_length > 2000):
            # Keep essential parts: file headers, error messages, test results
            if "FAILED" in content or "ERROR" in content:
                # Preserve error information completely
                pass
            elif content.startswith("import") or content.startswith("def "):
                # Code structure preservation
                lines = content.split('\n')
                new_content = '\n'.join(lines[:50] + ['...[CODE PRUNED]...'] + lines[-50:])
                msg.content = new_content
            else:
                # General pruning for other content
                new_content = (
                    content[:1000] + 
                    f"\n...[{content_length-2000} characters pruned]...\n" + 
                    content[-1000:]
                )
                msg.content = new_content
        
        pruned_messages.append(msg)
        total_content_length += len(getattr(msg, "content", ""))

    # If still over limit, remove oldest non-essential messages
    if total_content_length > max_context_length:
        pruned_messages = self._aggressive_pruning(pruned_messages)
    
    self.graph.update_state(self.config, {"messages": pruned_messages})

def _aggressive_pruning(self, messages):
    """Remove oldest messages while preserving recent context."""
    essential_types = (HumanMessage, AIMessage)  # Keep conversation
    non_essential = []
    essential = []
    
    for msg in messages:
        if isinstance(msg, essential_types):
            essential.append(msg)
        else:
            non_essential.append(msg)
    
    # Keep all essential, prune oldest non-essential
    max_non_essential = 10
    if len(non_essential) > max_non_essential:
        non_essential = non_essential[-max_non_essential:]
    
    return essential + non_essential
\end{lstlisting}

def save_session(self, filename="session.pkl") -> str:
    """Save complete session state with fallback strategies."""
    try:
        if self.checkpointer is None:
            return "Save not available: no checkpointer."
        
        # Attempt full binary serialization
        storage = getattr(self.checkpointer, "storage", None)
        if storage:
            try:
                with open(filename, "wb") as f:
                    pickle.dump({
                        "storage": storage,
                        "thread_id": self.thread_id,
                        "auto_mode": getattr(self, "auto_mode", False),
                        "usage_tracker": usage_tracker.__dict__,
                        "timestamp": datetime.utcnow().isoformat()
                    }, f)
                return f"Complete session saved to {filename}"
            except Exception as e:
                print(f"Binary save failed: {e}, trying JSON fallback...")
        
        # JSON fallback with structured summary
        try:
            snapshot = self.graph.get_state(self.config)
            messages = snapshot.values.get("messages", [])
            
            serial_msgs = []
            for m in messages:
                try:
                    serial_msgs.append({
                        "type": getattr(m, "type", None),
                        "content": getattr(m, "content", str(m))[:5000],  # Limit content
                        "tool_calls": getattr(m, "tool_calls", None)
                    })
                except Exception:
                    serial_msgs.append({"content": str(m)[:5000]})
            
            summary = {
                "thread_id": self.thread_id,
                "messages": serial_msgs,
                "usage": {
                    "total_tokens": getattr(usage_tracker, "total_tokens", 0),
                    "cost_est": getattr(usage_tracker, "cost_est", 0.0),
                },
                "auto_mode": getattr(self, "auto_mode", False),
                "timestamp": datetime.utcnow().isoformat()
            }
            
            json_filename = filename.replace('.pkl', '.json')
            with open(json_filename, "w", encoding="utf-8") as f:
                json.dump(summary, f, ensure_ascii=False, indent=2)
            return f"Session summary saved to {json_filename}"
            
        except Exception as e:
            return f"Error saving session fallback: {str(e)}"
    except Exception as e:
        return f"Error saving session: {str(e)}"

async def load_session(self, filename) -> str:
    """Restore session from saved state."""
    try:
        if filename.endswith('.json'):
            # Load JSON summary
            with open(filename, "r", encoding="utf-8") as f:
                summary = json.load(f)
            
            # Restore messages
            messages = []
            for m_data in summary.get("messages", []):
                if m_data.get("type") == "human":
                    messages.append(HumanMessage(content=m_data["content"]))
                elif m_data.get("type") == "ai":
                    messages.append(AIMessage(content=m_data["content"]))
                else:
                    messages.append(ToolMessage(content=m_data["content"]))
            
            # Update graph state
            self.graph.update_state(self.config, {"messages": messages})
            
            # Restore settings
            self.auto_mode = summary.get("auto_mode", False)
            usage_tracker.__dict__.update(summary.get("usage", {}))
            
            return f"Session restored from {filename}"
            
        else:
            # Load binary pickle
            with open(filename, "rb") as f:
                data = pickle.load(f)
            
            # Restore checkpointer storage
            if hasattr(self.checkpointer, "storage"):
                self.checkpointer.storage = data["storage"]
            
            # Restore session attributes
            self.thread_id = data.get("thread_id", self.thread_id)
            self.auto_mode = data.get("auto_mode", False)
            usage_tracker.__dict__.update(data.get("usage_tracker", {}))
            
            return f"Complete session restored from {filename}"
            
    except Exception as e:
        return f"Error loading session: {str(e)}"
\end{lstlisting}

\begin{lstlisting}[language=Python, caption=Human-in-the-Loop Approval Logic]
async def _handle_tool_approval(self, tool_calls) -> str:
    """Handle user approval for sensitive tools with flexible policies."""
    
    # Environment-based auto-approval
    auto_all = os.environ.get("CODING_AGENT_AUTO_APPROVE", "").lower() in {
        "1", "y", "yes", "true"
    }
    whitelist = {w.strip() for w in os.environ.get("CODING_AGENT_AUTO_APPROVE_WHITELIST", "").split(",") if w.strip()}
    
    for tc in tool_calls:
        name = tc.get("name")
        if name in SENSITIVE_TOOLS:
            # Runtime auto-mode toggle
            if getattr(self, "auto_mode", False):
                continue
                
            # Global auto-approve
            if auto_all or name in whitelist:
                continue
                
            # Interactive approval with diff display
            if name == "overwrite_file":
                await self._show_file_diff(tc)
                
            allow = await self._get_user_confirmation(name)
            if not allow:
                # Inject denial message into graph state
                denied_msg = ToolMessage(
                    tool_call_id=tc.get("id"), 
                    content=f"Error: User denied {name}."
                )
                self.graph.update_state(self.config, {"messages": [denied_msg]}, as_node="tools")
                return "denied"
    
    return "approved"
\end{lstlisting}

def parse_date(date_str):
    """Parse date with comprehensive format support."""
    formats = [
        '%Y-%m-%d', '%d/%m/%Y', '%m-%d-%Y', '%Y/%m/%d',
        '%d-%m-%Y', '%Y.%m.%d', '%m/%d/%Y'
    ]
    for fmt in formats:
        try:
            return datetime.strptime(date_str, fmt).date()
        except ValueError:
            continue
    raise ValueError(f"Unable to parse date: {date_str}")

def compute_tf_idf_vector(text, vocab, idf_scores):
    """Compute TF-IDF vector for a document."""
    words = text.lower().split()
    word_counts = Counter(words)
    total_words = len(words)
    
    vector = {}
    for word in vocab:
        if word in word_counts:
            # TF: term frequency
            tf = word_counts[word] / total_words
            # TF-IDF: TF * IDF
            vector[word] = tf * idf_scores.get(word, 0)
        else:
            vector[word] = 0.0
    
    return vector
\end{lstlisting}

\textbf{Cosine Similarity Implementation:}

\begin{lstlisting}[language=Python, caption=Proper Cosine Similarity Calculation]
def cosine_similarity(vec1, vec2):
    """Calculate cosine similarity between two vectors."""
    # Compute dot product
    dot_product = sum(vec1.get(word, 0) * vec2.get(word, 0) for word in set(vec1) | set(vec2))
    
    # Compute magnitudes
    mag1 = math.sqrt(sum(val ** 2 for val in vec1.values()))
    mag2 = math.sqrt(sum(val ** 2 for val in vec2.values()))
    
    # Avoid division by zero
    if mag1 == 0 or mag2 == 0:
        return 0.0
    
    return dot_product / (mag1 * mag2)
\end{lstlisting}

    """Calculate P(w2|w1) with Laplace smoothing."""
    V = max(1, len(self.vocab))  # Vocabulary size
    count_w1 = self.unigram_counts.get(w1, 0)

def score_sentence(self, tokens):
    """Score sentence using log-probabilities to prevent underflow."""
    log_prob = 0.0
    for i in range(len(tokens) - 1):
        w1, w2 = tokens[i], tokens[i + 1]
        p = self.get_probability(w1, w2)

\textbf{Temperature-Based Sampling:}

\begin{lstlisting}[language=Python, caption=Temperature Sampling for Diversity]
def generate_with_temperature(self, start_word, max_length=10, temperature=1.0):
    """Generate text with temperature-controlled sampling."""
    current_word = start_word
    output = [current_word]
    
    for _ in range(max_length - 1):
        if current_word not in self.bigram_counts:
            break
            
        candidates = self.bigram_counts[current_word]
        if not candidates:
            break
        
        # Apply temperature scaling
        if temperature != 1.0:
            logits = {w: math.log(cnt / sum(candidates.values())) / temperature 
                     for w, cnt in candidates.items()}
            # Softmax normalization
            max_logit = max(logits.values())
            exp_logits = {w: math.exp(logit - max_logit) for w, logit in logits.items()}
            total_exp = sum(exp_logits.values())
            probs = {w: exp / total_exp for w, exp in exp_logits.items()}
        else:
            total = sum(candidates.values())
            probs = {w: cnt / total for w, cnt in candidates.items()}
        
        # Sample from distribution
        words, probabilities = list(probs.keys()), list(probs.values())
        next_word = random.choices(words, weights=probabilities, k=1)[0]
        
        output.append(next_word)
        current_word = next_word
    
    return " ".join(output)
\end{lstlisting}

\subsection{Graph Design and State Management (25 Points)}
The core logic is implemented using \textbf{LangGraph} with a \textbf{ReAct} (Reasoning + Acting) architecture. The agent operates as a state machine where each turn involves reasoning about the current state and taking actions through tools.

\begin{itemize}
    \item \textbf{Nodes:} 
    \begin{itemize}
        \item \textbf{Agent Node:} Contains the LLM that reasons about the current state and decides what action to take
        \item \textbf{Tools Node:} Executes the selected tool and returns results back to the agent
    \end{itemize}
    
    \item \textbf{Edges:} 
    \begin{itemize}
        \item Conditional routing based on whether the agent needs to call a tool or can provide a final answer
        \item Loop back to agent node when tools are executed to continue reasoning with new information
    \end{itemize}
    
    \item \textbf{State Management:} 
    \begin{itemize}
        \item \textbf{Graph State:} Maintains conversation history (`messages`) and scratchpad for intermediate reasoning
        \item \textbf{Memory:} Uses `MemorySaver` checkpointer for session persistence across turns
        \item \textbf{HITL Integration:} Interrupts before tool execution to allow human-in-the-loop validation
    \end{itemize}
\end{itemize}

\textbf{Key Design Decisions:}
\begin{itemize}
    \item \textbf{ReAct Pattern:} Combines reasoning (LLM thinking) with acting (tool execution) in a structured loop
    \item \textbf{Interrupt-before-tools:} Allows the session manager to pause for human approval before executing potentially destructive operations
    \item \textbf{State Persistence:} Maintains context across multiple turns within a session
    \item \textbf{Modular Tools:} Clean separation between reasoning (LLM) and execution (tools) for better reliability
\end{itemize}

The graph is constructed using LangGraph's \texttt{create\_react\_agent} function, which automatically handles the ReAct flow, conditional routing, and state management. This design ensures the agent can handle complex multi-step tasks while maintaining safety through HITL controls.

\subsection{Human In The Loop (HITL) (15 Points)}
To prevent the agent from performing destructive actions (like deleting files or running dangerous commands) without permission, I implemented an interrupt mechanism.

\begin{enumerate}
    \item The graph is configured with \texttt{interrupt\_before=["tools"]}.
    \item Before executing a tool, the \texttt{InteractiveSession} checks if the tool is in the \texttt{SENSITIVE\_TOOLS} set (e.g., `execute\_shell`).
    \item If sensitive, the CLI prompts the user for confirmation (y/n).
    \item If denied, a mock error message is injected into the state so the agent knows the action failed.
\end{enumerate}

    """

def load_transactions(file_path):
    """
    Reads a CSV file manually (legacy code, no pandas allowed).
    Returns a list of dictionaries. Amounts are converted to floats when possible;
    missing or invalid amounts are set to None.
    """
    if not os.path.exists(file_path):
        raise FileNotFoundError(f"File not found: {file_path}")

    transactions = []

    with open(file_path, 'r') as f:
        lines = [ln for ln in f.readlines() if ln.strip()]  # Filter empty lines
        if not lines:
            return transactions  # Return empty list for empty files

        headers = lines[0].strip().split(',')

        for line in lines[1:]:
            values = line.strip().split(',')

            # Safely map values to headers with bounds checking
            record = {}
            for idx, header in enumerate(headers):
                val = values[idx] if idx < len(values) else ""
                record[header] = val

            # SAFE: Robust float conversion with error handling
            amount_raw = record.get('amount', '')
            try:
                amount_val = float(amount_raw) if amount_raw != "" else None
            except Exception:
                amount_val = None  # Graceful degradation for invalid data

            transaction = {
                'id': record.get('id', ''),
                'amount': amount_val,  # Now safely handles None values
                'currency': record.get('currency', ''),
                'status': record.get('status', ''),
                'date': record.get('date', '')
            }
            transactions.append(transaction)

    return transactions
\end{lstlisting}

    """

    This function iterates over a list of transaction dictionaries and sums up

\subsubsection{Mathematical Foundation of Vector Search}

Before diving into the fixes, it's essential to understand the mathematical principles the agent needed to implement correctly:

\textbf{Cosine Similarity Definition:}
The cosine similarity between two vectors $\vec{a}$ and $\vec{b}$ is defined as:
\[
\cos(\theta) = \frac{\vec{a} \cdot \vec{b}}{||\vec{a}|| \cdot ||\vec{b}||}
\]

Where:
\begin{itemize}
    \item $\vec{a} \cdot \vec{b}$ is the dot product: $\sum_{i=1}^{n} a_i b_i$
    \item $||\vec{a}||$ is the L2 norm: $\sqrt{\sum_{i=1}^{n} a_i^2}$
    \item $\theta$ is the angle between the vectors
\end{itemize}

\textbf{Why Normalization Matters:}
Without normalization, cosine similarity reduces to dot product, which favors longer vectors. For example, a document with twice as many words of a query term would score twice as high, even if semantically less relevant.

def calculate_cosine_similarity(vec_a, vec_b):
    """
    Calculate cosine similarity between two vectors.
    
    Cosine similarity measures the cosine of the angle between two vectors,
    providing a normalized measure of similarity that is independent of 
    vector magnitude. This prevents longer documents from artificially 
    scoring higher due to word count alone.
    
    Mathematical foundation: cos(theta) = (a*b) / (|a| * |b|)
    where a*b is the dot product and |a| is the L2 norm.
    """
    if len(vec_a) != len(vec_b):
        raise ValueError("Vectors must be of same length")

    # Compute dot product: sum(a_i * b_i for all i)
    dot_product = sum(a * b for a, b in zip(vec_a, vec_b))
    
    # Compute L2 norms: sqrt(sum(a_i^2)) and sqrt(sum(b_i^2))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    
    # Handle zero vectors (prevent division by zero)
    if norm_a == 0 or norm_b == 0:
        return 0.0
    
    # Return normalized cosine similarity
    return dot_product / (norm_a * norm_b)
\end{lstlisting}

class SimpleVectorizer:
    def __init__(self):
        self.vocab = {}
        self.idf = {}

    def build_vocab(self, chunks):
        """
        Builds vocabulary and computes Inverse Document Frequency (IDF).
        
        IDF helps identify terms that are discriminative across the corpus.
        Rare terms get higher weights, common terms get lower weights.
        """
        all_words = set()
        for chunk in chunks:
            words = self._tokenize(chunk)
            all_words.update(words)
        
        self.vocab = {word: i for i, word in enumerate(sorted(all_words))}
        
        # Compute document frequency (DF) for each term
        df = {word: 0 for word in self.vocab}
        total_docs = len(chunks)
        
        for chunk in chunks:
            seen_words = set(self._tokenize(chunk))
            for word in seen_words:
                if word in df:
                    df[word] += 1

        # Compute IDF with smoothing: IDF = log(N / df) + 1
        # The +1 prevents zero weights and provides smoothing
        import math
        self.idf = {word: math.log(total_docs / max(1, df[word])) + 1.0 
                   for word in self.vocab}

    def embed(self, text):
        """
        Convert text to TF-IDF weighted vector with normalization.
        
        This implements a simplified TF-IDF scheme that:
        1. Computes Term Frequency (TF) for each word
        2. Applies Inverse Document Frequency (IDF) weighting
        3. Normalizes the final vector for consistent similarity computation
        """
        words = self._tokenize(text)
        word_counts = Counter(words)
        
        # Initialize vector
        vector = [0.0] * len(self.vocab)
        
        # Apply TF-IDF weighting
        for word, count in word_counts.items():
            if word in self.vocab:
                index = self.vocab[word]
                # TF-IDF = TF * IDF
                tf = count / len(words) if words else 0.0  # Normalized term frequency
                idf = self.idf.get(word, 0.0)
                vector[index] = tf * idf

        # L2 normalization for cosine similarity
        norm = sum(x * x for x in vector) ** 0.5
        if norm > 0:
            vector = [x / norm for x in vector]

        return vector

    def _tokenize(self, text):
        """
        Advanced tokenization with preprocessing.
        
        Implements:
        - Lowercase normalization
        - Word boundary tokenization
        - Stopword removal to reduce noise
        """
        text = text.lower()
        tokens = re.findall(r'\b\w+\b', text)
        
        # Remove stopwords to focus on meaningful content words
        stopwords = {"the", "a", "an", "is", "of", "and", "to", "in"}
        return [token for token in tokens if token not in stopwords]

    This approach:
    1. Splits text into words rather than characters
    2. Maintains context continuity through overlap

\subsection{Project 3: Bigram Language Model - Probabilistic Text Generation}

\subsubsection{Problem Statement and Language Modeling Fundamentals}
The Bigram Language Model project aimed to build a statistical language model that could generate coherent text by learning patterns from training data. However, the implementation suffered from fundamental probabilistic modeling issues that caused generation failures and poor text quality.

\textbf{Core Issues Identified:}
\begin{itemize}
    \item \textbf{Zero Probability Problem:} Unseen word pairs received zero probability, causing division by zero and generation failures for any novel combinations.
    \item \textbf{Repetitive Generation:} Greedy sampling always selected the most probable next word, leading to repetitive, unnatural text patterns.
    \item \textbf{Numerical Instability:} Long sequence probabilities underflowed to zero due to multiplicative probability calculations.
    \item \textbf{Lack of Smoothing:} Maximum Likelihood Estimation (MLE) provided no robustness for sparse data scenarios.
\end{itemize}

\subsubsection{Mathematical Foundation of N-Gram Models}

Before analyzing the fixes, it's essential to understand the mathematical framework:

\textbf{Bigram Model Definition:}
A bigram model estimates the probability of a word given its immediate predecessor:
\[
P(w_i | w_{i-1}) = \frac{C(w_{i-1}, w_i)}{C(w_{i-1})}
\]

Where:
\begin{itemize}
    \item $C(w_{i-1}, w_i)$ is the count of the bigram $(w_{i-1}, w_i)$
    \item $C(w_{i-1})$ is the count of the unigram $w_{i-1}$
\end{itemize}

\textbf{Sequence Probability:}
The probability of a sequence is the product of conditional probabilities:
\[
P(w_1, w_2, \dots, w_n) = \prod_{i=1}^n P(w_i | w_{i-1})
\]

\textbf{The Sparsity Problem:}
In real text, many possible bigrams never occur, leading to $P(w_i | w_{i-1}) = 0$ for unseen combinations, making sequence probabilities zero.

def get_probability(self, w1, w2):
    """
    Calculate smoothed bigram probability using Laplace (add-one) smoothing.
    
    Laplace smoothing adds a small constant to all counts, ensuring no
    probability is ever exactly zero. This provides robustness for sparse
    data and prevents generation failures.
    
    Mathematical foundation: P_smooth(w2|w1) = (C(w1,w2) + 1) / (C(w1) + V)
    where V is vocabulary size (smoothing parameter)
    """
    V = max(1, len(self.vocab))  # Vocabulary size for smoothing
    
    count_w1 = self.unigram_counts.get(w1, 0)
    count_bigram = self.bigram_counts[w1].get(w2, 0)
    
    # Apply Laplace smoothing: add 1 to numerator, V to denominator
    smoothed_numerator = count_bigram + 1
    smoothed_denominator = count_w1 + V
    
    return smoothed_numerator / smoothed_denominator
\end{lstlisting}

\subsubsection{Phase 2: Log-Probability Scoring for Numerical Stability}

The agent implemented log-probability computation to handle long sequences:

\begin{lstlisting}[language=Python, caption=Log-Probability Implementation for Numerical Stability]
def score_sentence(self, tokens):
    """
    Calculate the log-probability of a token sequence.
    
    Uses log probabilities to avoid numerical underflow that occurs
    when multiplying many small probabilities (< 1.0) in long sequences.
    
    Log conversion: P(w1,w2,...,wn) = sum(log P(wi|wi-1))
    This prevents floating-point underflow for sequences > 20-30 tokens.
    """
    log_prob = 0.0
    
    for i in range(len(tokens) - 1):
        w1 = tokens[i]
        w2 = tokens[i + 1]
        p = self.get_probability(w1, w2)
        
        # Guard against numerical issues (though Laplace smoothing helps)
        p = max(p, 1e-300)
        
        # Accumulate log probabilities instead of multiplying raw probabilities
        log_prob += math.log(p)
    
    return log_prob
\end{lstlisting}

\subsubsection{Phase 3: Temperature Sampling for Text Diversity}

The agent replaced greedy sampling with temperature-controlled generation:

\textbf{Original Greedy Sampling:}
\begin{lstlisting}[language=Python, caption=Original Greedy Sampling - Repetitive Output]
def generate(self, start_word, max_length=10):
    """
    ORIGINAL: Greedy sampling - always picks most probable word
    PROBLEM: Produces repetitive, predictable text
    """
    current_word = start_word
    output = [current_word]

    for _ in range(max_length - 1):
        if current_word not in self.bigram_counts:
            break

        candidates = self.bigram_counts[current_word]
        if not candidates:
            break
        
        # GREEDY: Always pick the most frequent word
        next_word = max(candidates, key=candidates.get)
        
        output.append(next_word)
        current_word = next_word

    return " ".join(output)
\end{lstlisting}

\textbf{Enhanced Temperature Sampling:}
\begin{lstlisting}[language=Python, caption=Temperature-Controlled Sampling for Diversity]
def generate_with_temperature(self, start_word, max_length=10, temperature=1.0):
    """
    Generate text with temperature sampling for controlled diversity.
    
    Temperature controls randomness in sampling:
    - temperature < 1.0: More deterministic, prefers high-probability words
    - temperature = 1.0: Standard sampling from the distribution
    - temperature > 1.0: More diverse, increases probability of rare words
    
    This prevents repetitive text while maintaining coherence.
    """
    current_word = start_word
    output = [current_word]

    for _ in range(max_length - 1):
        if current_word not in self.bigram_counts:
            break

        candidates = self.bigram_counts[current_word]
        if not candidates:
            break

        # Calculate probabilities for all candidates
        total_count = sum(candidates.values())
        probs = {}
        for w, cnt in candidates.items():
            probs[w] = cnt / total_count

        # Apply temperature scaling
        if temperature != 1.0:
            # Convert to logits, apply temperature, renormalize
            logits = {w: math.log(p) / temperature for w, p in probs.items()}
            max_logit = max(logits.values())
            exp_logits = {w: math.exp(logit - max_logit) for w, logit in logits.items()}
            total_exp = sum(exp_logits.values())
            probs = {w: exp / total_exp for w, exp in exp_logits.items()}

        # Sample from the temperature-adjusted distribution
        words = list(probs.keys())
        probabilities = [probs[w] for w in words]
        next_word = self._random.choices(words, weights=probabilities, k=1)[0]

        output.append(next_word)
        current_word = next_word

    return " ".join(output)
\end{lstlisting}

def top_next(self, w1, n=3):
    """
    Return the top-n most likely next words after w1 with smoothing.
    
    This method provides model interpretability by showing the highest
    probability continuations. Useful for debugging and analysis.
    
    Returns list of (word, probability) tuples, sorted by probability.
    """
    # Consider all possible words in vocabulary
    candidates = list(self.vocab)
    probs = []
    
    for w2 in candidates:
        prob = self.get_probability(w1, w2)
        probs.append((w2, prob))

    # Sort by probability descending, then alphabetically for determinism
    probs.sort(key=lambda x: (-x[1], x[0]))
    return probs[:n]

def top_k_next_words(self, w1, k):

        next_words.items(), key=lambda item: item[1], reverse=True

\subsubsection{Training and Vocabulary Management}

The agent ensured robust training with proper vocabulary handling:

\begin{lstlisting}[language=Python, caption=Enhanced Training with Vocabulary Management]
def train(self, tokens):
    """
    Build bigram counts from tokenized text.
    
    This method constructs the statistical model by counting:
    1. Unigram frequencies for normalization
    2. Bigram frequencies for conditional probabilities
    3. Complete vocabulary for smoothing calculations
    
    The training process ensures all word pairs are captured
    for subsequent probability estimation.
    """
    for i in range(len(tokens) - 1):
        w1 = tokens[i]
        w2 = tokens[i + 1]

        # Count unigrams for normalization
        self.unigram_counts[w1] += 1
        self.bigram_counts[w1][w2] += 1
        
        # Maintain vocabulary for smoothing
        self.vocab.add(w1)
        self.vocab.add(w2)

    # Handle the final token
    if tokens:
        self.unigram_counts[tokens[-1]] += 1
        self.vocab.add(tokens[-1])
\end{lstlisting}

\subsection{Project Overview}
The goal of this project is to build an autonomous \textbf{Coding Agent} that has \textbf{Agency} — i.e., the ability to explore a codebase, edit code, execute tests and shell commands, and iterate until the requested task is completed.

\subsubsection*{Primary Capabilities}
\begin{enumerate}
  \item \textbf{Explore:} Inspect and list project files and folders to understand structure.
  \item \textbf{Edit:} Create and overwrite files to implement fixes or new features.
  \item \textbf{Execute:} Run shell commands such as `pytest` to verify changes.
  \item \textbf{Iterate:} Read test failures, update code, and re-run tests until green.
\end{enumerate}

\subsection{System Architecture}
\begin{itemize}
  \item \textbf{Core LLM:} The agent uses an LLM (configured via \texttt{langchain\_openai.ChatOpenAI}) as the reasoning engine.
  \item \textbf{Orchestration:} LangGraph implements a stateful ReAct-style graph that interleaves ``thinking'' (LLM) and ``acting'' (tools).
  \item \textbf{CLI:} A Rich-based CLI provides a user interface for natural-language commands and HITL confirmations.
  \item \textbf{Persistence:} \texttt{MemorySaver} checkpointer stores conversation and state during a session.
\end{itemize}

\subsection{Key Components and Capabilities}
\subsubsection{A. Toolset (The ``Hands'')}
The concrete tools available to the agent are implemented in \texttt{src/coding\_agent/agent/tools.py} and include:
\begin{itemize}
  \item \texttt{read\_file(path)}: returns file contents (guards against paths outside project root).
  \item \texttt{list\_files(dir)}: lists files and directories (skips hidden and ignored folders).
  \item \texttt{search\_files(pattern)}: recursive glob search for target files.
  \item \texttt{create\_file(path, content)}: creates a new file (HITL-controlled).
  \item \texttt{overwrite\_file(path, content)}: overwrites an existing file (HITL-controlled).
  \item \texttt{execute\_shell(command)}: runs commands in a timeout-limited subprocess (HITL-controlled).
\end{itemize}

\subsubsection{B. Graph Design and State Management (The ``Brain'')}
\begin{itemize}
  \item The graph is created via \texttt{create\_react\_agent(...)} in \texttt{backend.py} and is configured to interrupt before tool execution (\texttt{interrupt\_before=["tools"]}).
  \item A \texttt{TokenUsageTracker} callback collects token usage from LLM responses and estimates cost.
  \item \texttt{MemorySaver} is used (when available) for persisting state across turns; each session uses a unique \texttt{thread\_id}.
\end{itemize}

\subsubsection{C. Human-In-The-Loop (Safety)}
\begin{itemize}
  \item Sensitive tools are defined in \texttt{SENSITIVE\_TOOLS = \{"create\_file","overwrite\_file","execute\_shell"\}}.
  \item When the graph requests a sensitive tool, execution is paused and the CLI asks the user for confirmation showing the tool name and arguments.
  \item Two safety helpers are provided:
    \begin{itemize}
      \item \texttt{CODING\_AGENT\_AUTO\_APPROVE=1} to auto-approve all sensitive tools (use cautiously).
      \item \texttt{CODING\_AGENT\_AUTO\_APPROVE\_WHITELIST=tool1,tool2} to auto-approve only listed tools.
    \end{itemize}
  \item If denied, a \texttt{ToolMessage} with an error is injected into the state so the agent can react.
\end{itemize}

\subsection{Memory Management}
\begin{itemize}
  \item Conversation history lives in the graph state and \texttt{MemorySaver}.
  \item Pruning: large \texttt{ToolMessage} contents (over 2000 chars) are truncated (head + tail) after each turn to keep context manageable.
  \item Save/Load: \texttt{/save} attempts to pickle the checkpointer storage; if that fails, a JSON summary (messages + usage) is written as a fallback. \texttt{/load} tries to restore pickle first and falls back to loading the JSON summary (partial restore).
\end{itemize}

\subsection{Evaluation Projects (detailed checklist)}
For each evaluation project the agent:
\begin{enumerate}
  \item Lists files and inspects source code.
  \item Runs the project test suite (via \texttt{execute\_shell("pytest")}).
  \item Reads failing tracebacks and identifies buggy functions.
  \item Writes fixes using \texttt{overwrite\_file} (HITL approval required unless whitelisted).
  \item Re-runs tests until they pass.
\end{enumerate}

\section{Methods and Libraries (Implementation Details)}
This section summarizes the methodological choices and libraries used in the implementation of the Coding Agent. It maps directly to the assignment requirements and documents why each choice was made and how it was used.

\subsection{Graph-Based Control Flow}
\begin{itemize}
  \item \textbf{Why:} Agents require the ability to loop (plan, act, observe, revise). A graph provides explicit nodes and edges for this cyclic logic.
  \item \textbf{How:} LangGraph's ReAct-style agent is instantiated in \texttt{backend.py} via \texttt{create\_react\_agent(...)} with \texttt{interrupt\_before=["tools"]} so the graph can pause before tool execution and await human approval.
  \item \textbf{State:} The graph state (messages, tool calls, partial plan) is persisted in a checkpointer (MemorySaver when available) so subsequent turns can reference earlier context.
\end{itemize}

\subsection{Human-in-the-Loop (HITL)}
\begin{itemize}
  \item \textbf{Sensitive Tools:} \texttt{SENSITIVE\_TOOLS = \{"create\_file","overwrite\_file","execute\_shell"\}}; these trigger an interrupt.
  \item \textbf{Approval Flow:} The \texttt{InteractiveSession} inspects pending tool calls, prints a panel describing the tool and its arguments, and asks the user for approval with \texttt{Prompt.ask}.
  \item \textbf{Auto-approval Options:}
    \begin{itemize}
      \item \texttt{CODING\_AGENT\_AUTO\_APPROVE=1} -- global auto-approve (use with caution).
      \item \texttt{CODING\_AGENT\_AUTO\_APPROVE\_WHITELIST=execute\_shell,create\_file} -- whitelist specific tools for safe auto-approval.
    \end{itemize}
  \item \textbf{Denied Actions:} If the user denies a tool request, the session injects a \texttt{ToolMessage} error into the graph state so the agent can re-plan.
\end{itemize}

\subsection{Libraries \& Frameworks}
\subsubsection{LangGraph}
\begin{itemize}
  \item \textbf{Role:} Orchestration of the multi-step, stateful agent logic; supports looping and interrupt points.
  \item \textbf{Usage:} \texttt{create\_react\_agent(...)} is used to wire tools and the LLM into a ReAct agent; we rely on the graph's \texttt{stream()} API and \texttt{get\_state()} to manage execution.
\end{itemize}

\subsubsection{LangChain}
\begin{itemize}
  \item \textbf{Role:} Tool abstraction and LLM client helpers; \texttt{@tool} decorator (or a fallback) is used in \texttt{tools.py}.
  \item \textbf{Usage:} Tools such as \texttt{read\_file}, \texttt{create\_file} are implemented as functions that the graph can call.
\end{itemize}

\subsubsection{Rich}
\begin{itemize}
  \item \textbf{Role:} Nicely formatted CLI: \texttt{Console}, \texttt{Panel}, and \texttt{Prompt} are used to display agent messages, help, and to request confirmations.
  \item \textbf{Usage:} \texttt{interactive.py} uses Rich to present the welcome screen, help text, and to show HITL prompts.
\end{itemize}

\subsubsection{LLM (OpenAI / Chat Client)}
\begin{itemize}
  \item \textbf{Model:} Configured via \texttt{langchain\_openai.ChatOpenAI} (we used \texttt{gpt-4o-mini} in examples; \texttt{gpt-5-mini} was the suggested model).
  \item \textbf{Role:} Performs reasoning, creating plans, reading error traces, and proposing code changes. The LLM is not fine-tuned — it is guided by system prompts and the graph state.
  \item \textbf{Usage Tracker:} \texttt{TokenUsageTracker} monitors LLM outputs to estimate token usage and cost per turn.
\end{itemize}

\subsubsection{Other Utility Libraries}
\begin{itemize}
  \item \texttt{python-dotenv} for loading \texttt{.env} keys.
  \item \texttt{pytest} for evaluation and test automation.
  \item \texttt{pathlib}/\texttt{subprocess} for safe file and shell operations in tools.
\end{itemize}

\subsection{Python Environment}
\begin{itemize}
  \item \textbf{Recommended:} Python 3.11+.
  \item \textbf{Install:} \texttt{pip install -e .} will install required packages from \texttt{pyproject.toml}.
\end{itemize}

\subsection{Why these choices?}
\begin{itemize}
  \item Graph-based control provides explicit interrupt points and memory management, which linear chains cannot offer reliably.
  \item HITL ensures safety when executing destructive operations; whitelist and auto-approve options enable safe automation where desired.
  \item Rich gives a professional CLI which is essential for human supervisors to make quick decisions.
  \item Using standard LLM APIs keeps the agent flexible and model-agnostic.
\end{itemize}

\section{Expanded Methods and Libraries (Paragraph Form)}
This section restates and expands the key methodological choices and libraries used in the Coding Agent, formatted as continuous explanatory paragraphs rather than lists to improve readability and narrative flow.

Graph-based control flow was selected because agents must iterate: they generate a plan, execute actions, observe the outcomes, and revise plans as needed. Representing reasoning and acting as nodes within an explicit graph makes it straightforward to encode loops and decision points. In our implementation we use LangGraph to build a ReAct-style graph that alternates between LLM reasoning steps and tool actions. The graph is configured with an interrupt just prior to tool execution so that the session layer can pause and request human confirmation for sensitive operations. This architecture preserves intermediate state (messages, tool calls, partial plans) using a checkpointer; consequently the agent can continue long debugging sessions without losing context.

Human-in-the-Loop (HITL) is implemented as a safety layer: when the agent reaches an operation deemed sensitive—the creation or overwriting of files, or the execution of shell commands—the session prints a formatted prompt showing the tool and its arguments and asks the human for a clear yes/no decision. We added environment-driven controls to support automation in trusted contexts: a global auto-approve flag and a more restrictive whitelist that specifies particular tools allowed to run without confirmation. When the human denies a request, a structured error message is injected back into the graph state so the agent understands the failure and re-plans.

The implementation uses several libraries in specific roles. LangGraph serves as the orchestration layer that wires the LLM and tools into a stateful agent capable of loops and interrupts; methods in \texttt{backend.py} create and configure this graph. LangChain is used to define tools and wrap the underlying LLM client; the functions that read and write files or execute commands are exposed as callable tools so the graph can invoke them as actions. Rich is used to build a professional CLI: panels, formatted responses and interactive prompts make approval decisions and status messages clear to a supervising user. The LLM client (via OpenAI's Chat API wrappers) performs the reasoning and planning; we attach a token-usage callback so that the agent reports the resource usage for each turn.

Utility packages include \texttt{python-dotenv} for securely loading API keys, \texttt{pytest} for running test suites, and the standard \texttt{pathlib} and \texttt{subprocess} modules for implementing safe filesystem and process tools. The recommended runtime is Python 3.11 or higher; reproducible setup instructions are included earlier in the report.

Finally, these choices were made for practical reasons: a graph provides explicit control and resumability, HITL provides a clear safety boundary, Rich makes supervision usable, and standard LLM APIs keep the solution portable across provider models.

\section{Prose Summary (Lists Converted to Paragraphs)}
This section restates the report content in continuous paragraphs so that every item previously presented as a list is available in narrative form. The intention is to provide a readable single-pass description that covers the same material without enumerated bullets.

The agent's toolset implements safe, file-system aware operations the agent uses as its "hands." The tools include a file reader that returns file contents while ensuring the path is inside the configured project root, a directory lister that reveals the structure of the target project and skips hidden files, a recursive search implemented as a glob-based search over the project tree, and two write operations: a create-file function that builds parent directories as needed and writes UTF-8 content, and an overwrite-file function that replaces existing content. In addition there is an execute-shell tool that runs short commands (with a timeout) from the project root and returns stdout and stderr; because this tool can perform arbitrary actions it is treated as sensitive and is gated by the HITL approval system.

The agent's control flow is implemented as a stateful graph so it can loop when necessary: after planning and performing an action the agent observes the results, updates state, and may re-enter the planning phase. We built a ReAct-style graph using LangGraph; the agent alternates reasoning and acting nodes, and the graph is configured to interrupt before tool nodes so the session can check for human approval. The persistent state (messages, partial plans, and tool call history) is maintained using a checkpointer when available so long-running debugging sessions retain context between turns.

Human-in-the-Loop is enforced by explicitly marking the write and execution tools as sensitive. When the graph attempts to invoke such a tool the session prints a clear, formatted prompt showing the exact tool and the arguments the agent intends to use. The human must explicitly confirm; if the human denies the request the session injects a structured error message into the graph state so the agent understands that the action failed and can produce an alternative plan. For automated flows a global auto-approve flag exists, and a safer whitelist option allows specifying which tool names may be auto-approved in trusted runs.

LangGraph is the orchestration backbone that enables looping and stateful decision-making, and LangChain provides the tool abstractions and LLM client helpers used by the graph. The Rich library supplies the interactive CLI: Console prints formatted output, Panel separates responses, and Prompt collects HITL confirmations. The LLM is accessed via a standard Chat client and guided by system messages and the graph state; token usage is captured by a callback and presented to the user as a small cost estimate attached to agent responses.

Memory management includes pruning long tool outputs after a turn completes to avoid blowing the context window: if a tool returned a very large file content it is replaced in memory with a truncated summary containing the head and the tail separated by a clear marker. The save/load feature first attempts full binary serialization of the checkpointer storage and, if that isn't possible because of runtime-specific objects, falls back to saving a JSON summary of messages and usage; loading prefers the binary restore but will read the summary for a practical partial restore when necessary.

The testing workflow the agent uses is entirely self-contained: it inspects the project structure, reads tests and source, runs pytest to see failing traces, reasons about fixes, requests HITL approval for writes or test runs when needed, applies patches, and re-runs tests until all pass. This loop was exercised on three supplied evaluation projects where the agent identified issues, applied fixes, and validated the results by running the test suites to completion.

Finally, the project targets Python 3.11+ with dependencies declared in \texttt{pyproject.toml}. Reproducible setup steps, example system prompts used to guide the agent, and a small cost analysis appear earlier in the report. The deliverables include the source code, corrected evaluation projects, session logs, a PDF of this report, and a short demonstration video; these are prepared to be packaged into the required submission ZIP.
