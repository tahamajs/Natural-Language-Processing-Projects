\section{Project Objective}
Question 1 targets a practical Persian legal retrieval pipeline that supports evidence-grounded responses on Iranian legal texts. The final implementation emphasizes:
\begin{itemize}
\item deterministic preprocessing and indexing,
\item transparent node-level latency tracking,
\item retrieval traceability through source snippets,
\item reproducible artifact generation for report delivery.
\end{itemize}

\section{Implementation Scope}
The Q1 implementation is modularized under \texttt{answers/Q1/src} and orchestrated by \texttt{answers/scripts/run\_q1.py}. Core modules are:
\begin{itemize}
\item \texttt{q1\_pipeline.py}: loading, OCR fallback, chunking, TF-IDF indexing, retrieval, reranking, response generation,
\item \texttt{q1\_eval.py}: benchmark execution and RAGAS evaluation export,
\item \texttt{q1\_plots.py}: timing and evaluation plot generation.
\end{itemize}

\section{Pipeline Architecture}
The execution graph is:
\begin{enumerate}
\item dataset loading and OCR-aware text extraction,
\item chunking and metadata assignment,
\item TF-IDF vectorization and index persistence,
\item query rewrite, intent classification, metadata extraction,
\item top-$k$ retrieval with cosine similarity,
\item reranking to top-$n$ evidence blocks,
\item grounded answer synthesis with cited snippets,
\item node-level latency logging and benchmark export.
\end{enumerate}

The large gap between median and maximum total latency indicates query-dependent retrieval variance, especially for broader questions with wider lexical overlap in the corpus.
