\section{Project Objective}
Question 2 requires a live multi-tool travel assistant that can plan and answer scenario-based requests through external services. The final TravBot implementation integrates live APIs, vector retrieval, and an agent control loop, with performance logging suitable for reproducible reporting.

\section{System Scope}
The implementation is modularized under \texttt{answers/Q2/src}:
\begin{itemize}
\item \texttt{q2\_agent.py}: environment loading, dataset enrichment, vector-store setup, tool definitions, agent construction,
\item \texttt{q2\_scenarios.py}: scenario batch execution and structured logging,
\item \texttt{q2\_plots.py}: plot generation from scenario outputs.
\end{itemize}

\section{Live Integration Map}
TravBot currently integrates:
\begin{itemize}
\item OpenAI for LLM planning and synthesis,
\item Amadeus for flight and hotel retrieval,
\item Tavily for web-grounded weather and restaurant lookup,
\item Kaggle datasets for IATA and currency mapping,
\item LlamaParse for tourism document extraction,
\item LanceDB plus sentence-transformers for semantic retrieval,
\item LangGraph ReAct for multi-step tool orchestration.
\end{itemize}

\section{Execution Pipeline}
The deterministic execution sequence is:
\begin{enumerate}
\item runtime key loading from environment files,
\item live preflight checks,
\item Kaggle ingestion for airport/currency mappings,
\item tourism parsing and FAQ ingestion,
\item vector database initialization,
\item tool-wired agent construction,
\item scenario batch execution,
\item CSV/JSON logging and plot generation.
\end{enumerate}
